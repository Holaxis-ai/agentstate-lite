# Question

How should a user share selected project-plan knowledge with a broader audience that may not run Aslite, while retaining local ownership, explicit publication boundaries, and useful feedback loops?

# First-use signal

An anonymized test user wanted to point occasional collaborators at a project plan and let them ask questions, with selective synchronization to an established collaboration tool offered as one possible shape. This records the need, not a commitment to any named integration.

# Research boundaries

- Separate read-only publication, selective export/synchronization, cross-bundle relationships, and multi-human commenting; they carry different trust and architecture implications.
- Evaluate the existing Artifact, bundle View, catalog, and bundle-relationship primitives before proposing a new hosted or third-party integration.
- Keep the repository's frozen hosted/auth/admin scope frozen unless a human explicitly reopens it.
- Define what “selected” means and how accidental disclosure is prevented before evaluating transport mechanics.

# Desired output

A small decision record that identifies the user journey, information boundary, viable local-first options, rejected options, and whether any build-ready Task should follow.
