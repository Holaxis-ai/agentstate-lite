# Claude Code 2.1.226 compaction-checkpoint capabilities

## Decision summary

Claude Code exposes real lifecycle boundaries for a shared checkpoint protocol, but it does not expose a single event that both sees the pre-compaction context and can make the still-live Claude bearer synthesize a semantic checkpoint. `PreCompact` runs before manual or automatic compaction and can synchronously delay or block the boundary. Its payload does not contain the conversation and its hook process is outside the model context; the documented transcript file can lag in-memory state. Same-bearer continuation is available earlier at successful root or child turn completion through `Stop` and `SubagentStop`, with loop guards and an eight-block host cap. Restoration has a documented post-loss gate: `SessionStart` with `source: "compact"` runs before the next prompt and can inject up to 10,000 characters directly into context.

The consequence for the shared protocol is a constraint, not an architecture choice: meaningful semantic synthesis must already exist before `PreCompact`—for example from a prior same-bearer continuation—or the runtime must record a degraded checkpoint. The Claude adapter should only translate lifecycle events, identifiers, limits, and receipts. Durable state, generation/CAS rules, freshness, selection, and checkpoint schemas belong in the runtime-neutral core.

Target inspected: Claude Code `2.1.226`, [official release](https://github.com/anthropics/claude-code/releases/tag/v2.1.226) dated 2026-08-08; Darwin arm64, macOS 26.6 (25G72); research date 2026-08-08. Installed binary SHA-256: `013a1cf17df5ff1dcc189d5d6fd3fdd5f097ddc3cd41aa9992e99805574febbe`.

## Lifecycle mechanics relevant to the shared protocol

### Pre-loss path

1. At an ordinary successful root or child stop, a sync `Stop`/`SubagentStop` adapter can consult shared state.
2. If a fresh semantic checkpoint is required, the adapter can continue that same conversation with bounded instructions. `stop_hook_active` and a durable attempt/generation guard prevent repeated requests; Claude’s eight-block limit is a final host guard, not a protocol substitute.
3. The bearer must persist the semantic result through a normal tool/CLI write before the attempt can be marked durable. Hook return, transcript text, or assistant prose alone is not a durable receipt.
4. At `PreCompact`, the adapter can perform a fast readiness/freshness check. If the required durable checkpoint already exists, allow compaction. If not, it can block only where the configured policy and recovery mode make that safe. It cannot create model semantics at this callback.

This description deliberately does not select checkpoint schema, storage layout, or freshness policy. Those are shared-core responsibilities.

### Post-loss path

1. Claude finishes compaction and exposes `PostCompact` with the generated `compact_summary`.
2. Claude runs `SessionStart` with `source: "compact"` before the next prompt. Exact order between these two callbacks is not documented.
3. The adapter asks the shared core to select a compatible checkpoint using project/runtime/bearer lineage plus generation and freshness rules. Because `session_id` can represent simultaneous active carriers, ambiguous lineage must not silently auto-select.
4. The adapter injects one bounded capsule no longer than 10,000 characters through `additionalContext`; oversize file indirection is a degraded transport unless the shared protocol explicitly handles it.
5. Handler/host acceptance and actual model use remain separate receipt levels.

### Resume, fork, and replay

- Ordinary resume preserves session lineage; fork creates a new session. A fork may inherit semantic ancestry, but it must get independent carrier/checkpoint concurrency state.
- Two simultaneous resumes can share the same session ID and transcript. A Claude adapter therefore cannot use `session_id` as a mutex owner or unique active-bearer ID.
- Context injected during prior events can replay from the transcript on resume. A fresh `SessionStart` callback runs again, so capsules require stable IDs and idempotent wording; replay must not be treated as a fresh restore receipt.
- Claude transcript JSONL is documented as internal and release-variable. It may be used only as explicitly degraded evidence, not as the protocol database or parser contract.

## Claude-specific adapter contract

The adapter may own only the following runtime facts:

- Map `PreCompact.trigger` (`manual`/`auto`) to a shared pre-loss boundary notification and preserve the proactive-auto versus recovery-error blocking distinction.
- Map `Stop`, `StopFailure`, and `SubagentStop` into successful-stop, error-observation, and child-stop signals, including `stop_hook_active` and the host’s eight-block limit.
- Map `PostCompact` and `SessionStart.source == "compact"` into post-loss observations/restoration opportunities without assuming their undocumented relative order.
- Normalize Claude fields (`session_id`, optional `prompt_id`, optional `agent_id`/`agent_type`, cwd/project hint) into shared identity inputs while recording which components are missing or ambiguous.
- Enforce host transport limits: stdin JSON, non-TTY execution, configured timeout, exit-code/JSON semantics, parallel handler delivery, and the 10,000-character direct-context ceiling.
- Emit evidence-level receipts for callback observation and host acceptance; never label either as semantic use.

The adapter must not own a Claude-specific journal, generation head, checkpoint schema, freshness algorithm, durable store, transcript parser, daemon, tmux carrier, or hidden model conversation. It calls a shared core for CAS, persistence, selection, redaction, and receipts. This is the boundary that keeps the protocol portable.

## Current installation seam

The repository already has a useful, narrowly tested seam in `packages/cli/src/commands/hook.ts`: a pure settings updater plus an absolute self-reexec command. Its tests demonstrate preservation of foreign hooks and keys, exact managed-handler deduplication, idempotent install/uninstall, and refusal to rewrite malformed settings. Extension should preserve these properties and add capability/version negotiation. In particular, one managed dispatcher command is preferable to independently edited stateful handlers only if its event routing remains observable and foreign entries remain untouched; the research does not prescribe the final topology.

The installed `claude --help` includes `--autocompact`, `--include-hook-events`, `--resume`, `--fork-session`, and `--session-id`. Current official CLI docs also list `--init-only`, but because local help omits it, the adapter/test harness must probe actual acceptance rather than assuming help/document parity.

## Required isolated probes for implementation validation

These are gaps, not prerequisites for comparing runtime architectures:

1. Record event streams for manual compaction and forced automatic compaction, including timestamps and completion order for PreCompact, PostCompact, and compact-sourced SessionStart.
2. For proactive-auto and API-limit-recovery modes, test PreCompact allow, exit 2, block JSON, generic nonzero, invalid JSON, timeout, and killed handler.
3. Exercise two or more parallel handlers, duplicate handlers across settings scopes, and plugin duplicates; record blocker aggregation and additional-context ordering.
4. Measure direct-context boundaries at 9,999/10,000/10,001 characters with multiline Unicode and invalid JSON; distinguish direct injection from file-preview fallback.
5. Verify Stop continuation exactly once with a nonce, `stop_hook_active`, and the eight-block cap; separately test interrupt, API failure, SIGINT, SIGTERM, and abrupt kill.
6. Run a root plus two sibling subagents; force or approach child compaction; record `agent_id` stability, sibling isolation, child stop behavior, and child event ordering.
7. Test ordinary resume, fork, and two simultaneous isolated resumes. Prove that shared-core ambiguity handling prevents session-ID-only automatic selection.
8. Rename/remove/replace the installed agentstate-lite executable and vary permissions/schema/version; record each lifecycle event’s exit/timeout behavior and verify degraded receipts never claim readiness.
9. Capture only redacted fixtures in a temporary Claude configuration/home and temporary agentstate-lite bundle. Do not inspect or mutate a user’s live Claude transcripts or settings.

## Bottom line

Claude Code 2.1.226 is compatible with a runtime-neutral compaction-checkpoint protocol only as a **conditional lifecycle carrier**. It gives strong pre/post boundary signals, a bounded restoration channel, and proactive same-bearer continuation at successful stops. It does not give a compaction-time same-bearer synthesis call, a unique active-carrier identifier, a native semantic-use acknowledgement, or complete failure/ordering guarantees. The shared core must therefore handle durability, concurrency, freshness, ambiguity, and receipts, while the Claude adapter remains a thin translation layer with explicit degraded states.
