# Acceptance criteria

## Rulings encoded

1. A valid Brian-inspected/Mike-approved pair and the inverse both pass in prerelease and stable tiers; same-operator pairs continue to pass.
2. Each receipt still independently requires an allowed signer, signed actor equal to uploader, candidate tuple equality, upload before finalize dispatch, and legal inspection-before-approval ordering.
3. The public reconciler receipt keeps required input field `actor` for every actor-bearing state. One internal map namespaces it to `inspected_by`, `approved_by`, `rejected_by`, `promoted_by`, or `rolled_back_by` during merge. Same-state identical replay is idempotent, same-state different actor rejects, and different actors across every reachable actor-bearing state do not collide. Ordering proof output exposes both decision actors without a misleading singular actor.
4. Signed canonical receipt bytes continue to bind `stage_id + version + tarball_sha256 + draft_release_id` and do not bind `run_id`.
5. Prerelease approval-without-inspection passes with `verified: [approved]`, `missing: [inspected]`, ledger `state: staged`, and a required public missing-inspection stamp. Stable approval-without-inspection remains red.

## M1 asset authority

6. One pure parser owns the exact `receipt-(inspected|approved|status)-<live UUID stage ID>.json` grammar. Pre-stage capture mode has no current stage and treats every valid auxiliary only as residual for the core-two check; finalize mode receives the chain-verified current stage and distinguishes current decision receipts, current status, and siblings. The dry-run synthetic stage token and malformed lookalikes never acquire auxiliary status.
7. Recognized sibling-stage residue may be tolerated during read-only draft verification but is never treated as current evidence and cannot survive into the published inventory.
8. For each current decision receipt, the SHA-256 of the exact downloaded file equals the selected GitHub asset metadata digest; the ordering proof persists exact `{id,name,digest}`. The chain proof similarly persists sorted exact core triples.
9. A pre-existing `receipt-status-<currentStageId>.json` is never trusted by name. If no stamp is required it is removed before publication; if a stamp is required the generated file's digest is fixed before retry-safe `--clobber`, the final re-query finds one matching name/digest, and the final proof records its newly observed asset ID.
10. The pure publication planner emits a machine-readable manifest bound to `draft_release_id`, with a sorted unique delete list of exact numeric `{id,name,category}` entries and the exact keep proof. The live executor deletes only those asset IDs through the release-asset ID endpoint. Already-absent IDs are retry-tolerated only because the final re-query remains authoritative.
11. The write-capable finalize job re-queries the draft after cleanup/clobber and immediately before `immutable-release`. The exact final allowlist is retained core triples + unchanged current receipt triples + generated current status iff required. Same-name replacement of a verified receipt (changed ID or digest) rejects; status name/digest must equal generated bytes and its final ID is observed; no sibling, malformed, arbitrary, duplicate, or unverified auxiliary remains.
12. A forged current status, arbitrary binary under a receipt-like sibling name, stale sibling status, or same-name replacement of a verified receipt all fail to ride to publication. A normal unexpected asset remains red.

## Workflow-owned body authority

13. Receipt status in the GitHub release body is one clearly delimited workflow-owned block. A pure normalizer accepts zero or one well-formed block, rejects duplicate/unbalanced/nested markers, preserves unrelated notes, replaces the block when a stamp remains required, and removes it when no stamp is required.
14. After body PATCH, the finalizer re-queries the draft and proves exactly one current block agreeing with the ordering result, or no owned block when no stamp is required. Required->required retry never appends a duplicate; required->full-receipts retry removes the stale claim.

## L1/L2 and workflow safety

15. An inspection checksum mismatch exits nonzero, emits no receipt/upload, prints the reject guidance, and removes its `aslite-release-inspect-*` scratch directory and downloaded suspect tarball before process exit, including batch mode unwinding.
16. The live status upload is explicitly retry-safe with `--clobber`. A prior same-name status asset cannot block a legitimate rerun and cannot survive unchanged.
17. Dry-run runs the same classifier/planner/report path but never invokes the cleanup executor, upload, body PATCH, or release publication. An injected command runner or stubbed `gh` transcript empirically records zero mutation calls; a workflow substring assertion alone is insufficient.
18. Workflow ordering is mechanically pinned as verify downloaded current evidence and metadata digests -> generate plan/status/body -> live ID-only normalization -> re-query -> verify exact asset triples and owned body -> publish.

## Gates and handoff

19. Focused affected suites pass, the exact-SHA independent review approves, targeted adversarial QA passes, and then `npm run check` exits 0 on the same SHA.
20. No plugin version/bundle artifact is hand-bumped or rebuilt. No PR is created or merged by an agent. The pushed feature branch is handed to Brian with a paste-ready PR title/body.
21. The PR handoff explicitly asks Brian to verify the three committed allowed-signers key lines as the intended current Brian/Mike GitHub SSH keys. This remains human-owned evidence.

# Implementation targets

- `scripts/release-state.mjs`: keep `actor` in every actor-bearing state's required receipt fields; map it internally to one state-specific ledger key during merge. Do not change the manual reconciler receipt API.
- `scripts/release-ordering.mjs`: remove cross-receipt same-actor rejection; expose per-decision actors; own the single strict auxiliary-name parser, its pre-stage/finalize classification modes, publication-plan/final-inventory authorities, and the delimited release-body normalizer.
- `scripts/release-verify-ordering.mjs`: hash downloaded receipts and compare them to GitHub digests; persist exact receipt triples; materialize and hash expected status; emit the draft-bound sorted cleanup manifest; provide the injectable/stubbable live ID-only executor; verify post-mutation asset triples, final status ID, and re-queried owned body.
- `scripts/release-receipts.mjs` and `scripts/release-verify-chain.mjs`: consume the one parser in explicit pre-stage versus finalize mode. Preserve exact core-two verification and persist sorted core triples in the chain proof; malformed lookalikes remain unexpected extras.
- `.github/workflows/release-finalize.yml`: in the write-capable finalize job, apply the live ID-only manifest, upload a required current status with `--clobber`, replace/remove the owned body block, re-query draft metadata/body, run the exact final proof, then publish. Dry-run calls only the planner/report path.
- `scripts/release-inspect.mjs`: replace the in-try hard `process.exit(1)` mismatch path with unwinding that reaches `finally`; retain nonzero CLI result and reject guidance.
- `scripts/release-state.test.mjs`: prove `actor` remains the input field; same-state identical/different replay behavior; and distinct actors across every reachable actor-bearing branch.
- `scripts/release-ordering.test.mjs`: replace the old cross-operator-red row with split-role green rows; pin prerelease approval-only; test both grammar modes; local receipt SHA versus metadata digest; exact proof triples; sorted/draft-bound cleanup; final status digest/ID; same-name receipt replacement rejection; body required->required and required->none retry convergence; the highest-risk red probe below; and the mismatch scratch cleanup subprocess fixture (or a dedicated `release-inspect.test.mjs` registered in `test:scripts`).
- `scripts/release-receipts.test.mjs`: replace blanket receipt-name tolerance with pre-stage residual and finalize current/sibling category tests plus malformed-name rejection; prove core triples enter the chain proof.
- `scripts/release-workflow.test.mjs` plus an adapter/subprocess transcript test: require literal `--clobber`, ID-only cleanup, body normalization, final re-query/gate after all mutation and before publication, and empirically zero gh/publish mutations in dry-run.
- `package.json`: change only if a dedicated new test file is introduced; otherwise no additional script registration is needed.

# Targeted adversarial QA rows

- Brian inspect -> Mike approve and Mike inspect -> Brian approve: both accepted; proof and ledger retain both identities.
- Signed actor/uploader mismatch remains red; unlisted signer remains red; approval upload before inspection remains red.
- Prerelease approval-only yields approval receipt + newly generated missing-inspection stamp; stable equivalent rejects.
- Both valid receipts + forged current status: forged status cannot survive and final inventory contains no status.
- Missing inspection + pre-planted current status: generated expected status replaces it; final digest matches generated bytes; rerun is not name-collision blocked.
- Required-stamp -> required-stamp retry replaces the workflow-owned body block without duplication; required-stamp -> full-receipts retry removes both the stale status asset and stale body claim while preserving unrelated notes.
- Arbitrary binary under a syntactically valid sibling receipt/status name: tolerated only before normalization, removed/excluded before final proof, never published.
- Malformed receipt-like name and ordinary `evil.tgz`: fail closed as unexpected assets.
- Sibling valid signed/unsigned residue does not affect current receipt selection and cannot appear in final inventory.
- Inspection mismatch: nonzero, no upload/receipt, reject command printed, controlled TMPDIR contains no leaked `aslite-release-inspect-*` directory or tarball.
- Dry-run over the same residue reports the sorted cleanup plan but a stubbed command transcript records zero cleanup/upload/body PATCH/publish calls.

## Highest-risk M1 red probe

Construct an approval-only prerelease after signature verification. The ordering proof binds approval `{id:501,name:receipt-approved-<stage>.json,digest:sha256:A}` and generated status digest `sha256:S`. A final draft with the same approval name but `{id:777,digest:sha256:B}` and the right status name but digest `sha256:F` must reject. Holding all names constant, independently restore the exact approval triple and generated status digest; only the fully restored fixture may pass. Add one syntactically valid sibling auxiliary to that passing fixture; final verification must reject until normalization removes its exact ID. As a load-bearing red check, temporarily reduce final verification to name-only: the test suite must fail because the replacement or sibling case stops throwing.
