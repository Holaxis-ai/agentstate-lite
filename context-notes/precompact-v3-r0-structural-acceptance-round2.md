## Blocking findings

### 1. Installed-Claude executability is still absent

No R0 file invokes `/Users/brian/.local/bin/claude`, its pinned target, or any Claude executable. `r0-run-case.mjs` invokes `process.execPath` with `scripts/r0-inert-hook.mjs` and feeds it a synthesized event. The only tests likewise execute Node or call the production adapter in process.

There is no settings file or command registering the inert hook with Claude. Because the scripts are mode `0644`, a valid settings command would need an exact absolute Node executable plus exact script and manifest paths; none exists. The fixture also does not bind evidence to the currently installed 2.1.221 binary or its digest.

Consequently, direct-runner success cannot answer whether Claude 2.1.221 accepts the output schema, delivers `SessionStart(source=compact)` context, honors PreCompact blocking, or honors SessionStart `continue:false` before producing a response.

### 2. No isolated settings lifecycle or restoration proof exists

The fixture never creates an isolated `CLAUDE_CONFIG_DIR`, never snapshots or hashes settings before installation, never installs hook entries, never restores exact bytes, and never checks preservation of foreign hooks. It has no cleanup or crash-restoration path. Its runner writes under repository-local `.r0-live`, not a named isolated host/config/evidence root.

There is therefore no structural basis to claim that a live run would be inert with respect to user-global/project settings or foreign hook handlers.

### 3. Manual and automatic positive journeys remain indistinguishable labels

Both `positive-manual` and `positive-automatic` synthesize exactly one event: `SessionStart` with `source:"compact"`. No PreCompact event is observed, no trigger is captured, and no event-order chain exists. Since SessionStart itself does not identify whether the initiating compaction was manual or automatic, the two cases can only be distinguished by the preceding observed PreCompact event. The fixture omits it.

The hook manifest permits only one expected event, so the current contract cannot record or validate `PreCompact(manual|auto) -> SessionStart(compact)` in one installed session.

### 4. Negative coverage remains incomplete and non-hosted

The direct `negative-precompact` mode always synthesizes `trigger:"manual"`; there is no direct-runner automatic negative case. The TypeScript unit helper labels manual/automatic negative cases but only calls a fake authority through the production adapter and expects `HANDOFF_SCHEMA_INVALID`, not the standalone hook's `R0_NEGATIVE_BLOCK` output.

The `negative-session` direct case proves only that Node prints `{continue:false,...}`. It does not prove Claude invokes that hook or suppresses the first assistant response. The sole recorded artifact is this direct case and contains no host observation.

### 5. Evidence provenance remains insufficient and partially manufactured

`r0-run-case.mjs` stores a parsed event object that it created itself, not exact stdin bytes received from Claude. It records only stdout, stderr, and exit code. It captures no installed executable identity, settings bytes/digest, hook command, script/manifest digests, process signal/timeout/EOF, event sequence/timestamps, actual transcript, native summary, or first-response/no-response evidence.

`packages/cli/test/support/r0-live-rail.ts` still hardcodes `sentinelInTranscript:false` and `sentinelInNativeSummary:false` without reading either artifact. The tests then assert those constants. This can manufacture the central absence claims.

`r0-rail-collector.mjs` defines a separate verdict requiring string fields named `stdin_raw`, `stdout_raw`, `stderr_raw`, `claude_transcript`, and `native_summary`; the runner never produces that shape and no code invokes the verdict. Its verdict checks only types and nonempty stdout, not sentinel placement/absence, schemas, ordering, blocking effect, executable identity, timeouts, or digest binding.

The sole `.r0-live` evidence file points to a transcript path for which no file exists. It provides no native-summary reference at all.

### 6. The STATIC/LIVE boundary is a mutable label, not a gate

The collector creates a `mode:"STATIC"` manifest, but the hook rejects that manifest because it requires `mode:"LIVE"`. The collector output is therefore unusable by the hook.

Separately, `r0-run-case.mjs` unconditionally creates `mode:"LIVE"` itself and immediately invokes the hook directly. No reviewed authorization receipt, reviewer identity, exact-byte digest, or compare-and-swap transition controls this promotion. Any caller able to run the static script can self-mint the `LIVE` label.

This is the opposite of the required boundary: STATIC fixture validation and authorization-gated LIVE execution are disconnected, while the direct unit runner crosses the label boundary automatically.
