## Independent built-CLI probe

An inline no-harness-file probe exercised six negative OpenCode sources one at a time:

1. noncanonical runtime only with canonical local-dev executable;
2. noncanonical executable only with canonical runtime;
3. noncanonical npm runtime and executable;
4. direct noncanonical local-dev executable;
5. direct noncanonical marketplace executable;
6. the original cross-prefix npm source (`/opt/runtime-a/bin/node` plus `/opt/npm-b/lib/node_modules/@holaxis/aslite/dist/agentstate-lite.mjs`).

For every negative row, the probe seeded an exact generated-wrapper source, set mode 0640, snapshotted bytes and mode, and drove the freshly built CLI through status, install, and uninstall. All 6/6 were reported unmanaged, install refused with exit 1, uninstall emitted the unmanaged OpenCode preservation note, and exact bytes plus mode survived all three operations. A positive empty-base control installed a generated OpenCode plugin, reported it current, and removed it on uninstall (1/1).

The first probe attempt incorrectly asserted the aggregate uninstall receipt's `hook.changed` must be false. It stopped on the first row because the earlier refused OpenCode install had still installed Claude/Codex hooks, which uninstall legitimately removed; therefore aggregate `changed: true` does not mean the OpenCode plugin changed. The corrected probe uses the actual uninstall receipt schema (aggregate boolean plus host-specific preservation note) and exact OpenCode bytes/mode as the mutation oracle. This was a QA harness-model correction, not a product failure.
