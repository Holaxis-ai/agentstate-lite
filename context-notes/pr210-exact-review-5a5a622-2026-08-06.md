## Reviewed model and result

The repair preserves that separation:

- `hook-compatibility.ts` requires every absolute runtime or executable token to already be its native canonical lexical spelling before any npm, repository-local, or marketplace layout can grant ownership. It never normalizes foreign text into permission.

- `install-authority.ts` recognizes a `local-dev` artifact physically installed in the scoped npm layout, then reuses the existing durable prefix/PATH/bin/package/runtime proof. It keeps `state: local_dev`, emits the proven canonical `<prefix>/bin/node`, and returns `unknown` when any proof fact fails. Ordinary repository local-dev and marketplace behavior remain unchanged.
- The package verifier realpaths its scratch root before deriving the prefix, sanitizes inherited `npm_config_*` state, models the supported POSIX prefix Node launcher, and verifies the emitted installed command rather than weakening the production classifier.
